Interactive Walkthrough

The model, exposed as a product surface.

Start with setup, run a prompt, then move stage by stage through the model’s internal path from text to next-token choice.

Model Setup

Choose a model and load it locally.

The first run downloads the weights into the browser cache. After that, reloads are much faster.

Use the local server URL. This tool is more reliable on http://127.0.0.1:8123/tools/inside-a-llm.html than on file://.
Choose a model and click load. The first load downloads it, caches it, and runs entirely on your device.
Prompt

Run a prompt through the model.

Start with a short phrase so the intermediate stages stay easy to inspect.

Stage 01

01 Tokenization

The tokenizer splits your text into units and maps each unit to a vocabulary ID. The model only sees these numbers.

Stage 02

02 Embeddings

Each word becomes a high-dimensional vector. This view shows the first 48 values per word as a compact heat strip.

Negative Positive Brighter = larger magnitude
Stage 03

03 Token relationships

Real cosine similarity across the token vectors. Brighter cells mean the word vectors sit closer in embedding space.

Why this view exists: browser-friendly model exports usually expose token generation and logits, but not raw attention tensors. This stage uses a compact embedding model to show real vector structure and relative closeness with numbers you can inspect.
Stage 04

04 Next-token prediction

This is the model’s actual probability distribution over what comes next, computed directly from the output logits.

0.8
Temperature controls variance. Lower values keep the model near its top choice. Higher values flatten the distribution, giving lower-probability tokens more room to appear.
Runtime

Everything runs in-browser.

The page uses WebGPU when available and falls back to WASM when it is not. That means performance depends on the device and browser.
